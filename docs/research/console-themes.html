The shell holds latchkey's twenty sections as comfortably as tripline's twelve. Every option keeps one theme for all the apps and swaps only the accent: flip tripline / runsheet and light / dark on each to compare.

One tinted neutral, dressed

A single mauve-tinted neutral shared by every app (chroma so low that red, amber and green status still pop), Geist Sans and Mono, 6px radius. the org switcher · researched 12 sep 2026

Anchor: a rooted switcher, a scope chain, an unmistakable staff lane

Twenty-nine switcher patterns verified across Vercel, Linear, Slack, Notion, GitHub, Supabase, Sentry, Stripe, Cloudflare, Google Cloud, AWS, Clerk, Auth0, Okta and WorkOS; three independent designs (speed-first, clarity-first, simplicity-first) were judged against them. Clarity-first won, with a dozen ideas grafted from the other two.

what 2026 consoles do · researched 12 sep 2026

Thirteen decisions the shell inherits

Five researchers swept navigation, data density, colour, interaction and typography across shipping developer and ops products; a skeptic checked each of the 35 claimed trends against primary sources (all 35 held); one synthesis turned them into decisions for our shell. The mockups above already reflect the ones that show on screen.

2026 ops consoles have converged on a single, calm shell: a collapsible-to-icons sidebar with flat label-only groups and an org switcher in its header, a sticky page action bar carrying breadcrumbs, tabs and a visible ⌘K trigger, and a command palette that has grown from navigation into a context-aware action surface. Data surfaces are built as two primitives (clickable list rows for streams, true grid tables for comparable numbers) with named density modes, tabular numerals, mono scoped to identifiers, and row detail in a resizable right panel, while workflow entities keep full pages and destructive actions get stakes-proportional confirmation. Visually the dialect is restraint: OKLCH-authored two-layer tokens with a tinted neutral shared across products and only the accent varying, separately tuned dark scales, hairline alpha borders with shadows reserved for floating layers, 4-8px radii, 13px body with 12px labels, a branded sans+mono pair, and 16px/1.5px stroke icons, all frozen in tokens and lint rules to resist the generic AI-template look.

Navigation & shell

Ship one single-tier shadcn Sidebar (SidebarProvider collapsible="icon", variant="inset") at 240px expanded / 48px icon rail, toggled by Cmd/Ctrl+B and SidebarRail hover, state persisted in a cookie (sidebar_state) so first paint matches, with Tooltip labels on every icon-only item and SidebarMenuSkeleton while nav data loads.

Collapsible-to-icons sidebars with persisted state are now table stakes: shadcn ships it as the default template with cmd/ctrl+B and cookie persistence; Vercel's Jan-Feb 2026 redesign replaced tabs with a hideable resizable sidebar; Atlassian's Dec 2025 full-height sidebar added Ctrl+[ because the collapse button was hard to find; Supabase (Feb 2025) and Grafana (localStorage docked state) persist the preference; NN/g's caveat that icon rails only work for daily-use apps holds for a developer/ops audience. Sentry's two-tier rail (74px + 190px panel) is built for a multi-product suite; ~20 latchkey sections cluster into 6 groups and fit one tier.

Navigation & shell

Cap the sidebar at two levels: a per-user Pinned group (SidebarGroup + SidebarMenuAction pin/unpin, seeded per role, plus a 5-item Recent list) at the top, then 5-6 task-oriented groups with non-interactive SidebarGroupLabel headers (11px, uppercase, tracking-wide, text-muted-foreground, 16px gap between groups) and 28px SidebarMenuButton rows (size="sm", 13px text); no SidebarMenuSub accordions, and each entity's sub-pages become tabs in the page action bar. latchkey groups: Directory (Identities, Sessions, Invitations), Access (Clients, Grants, Scopes), Tenancy (Tenants, Organizations), Security (Policies, Audit), Settings; tripline: Issues, Performance, Releases, Alerts, Settings; runsheet: Runbooks, Runs, Incidents, Settings.

Auth0's Sept 2026 dashboard refresh (an IdP with essentially latchkey's section count) moved to label-only group headers and six task-oriented sections; GitLab Pajamas (July 2026) states there is no third nav level; Grafana Saga sends level 4 to page tabs; Primer pairs NavList with UnderlineNav and breadcrumbs. Pinned/starred layers are established at Linear (Dec 2024 hide/reorder/More), Sentry Issue Views (June 2025 starred views in nav), Grafana Bookmarks (11.2) and GitLab (seeded default pins), and reduce traversal of a long IA without hiding it.

Put one shared OrgSwitcher (shadcn sidebar-07 TeamSwitcher pattern: 24px avatar + org name + chevron in a DropdownMenu inside SidebarHeader, collapsing to the avatar button in icon mode) in all three apps, move the personal account menu to the top-right of the page action bar, and treat the next scope level as a page-header filter rather than a second sidebar: tripline project/environment selector, latchkey active-tenant selector, runsheet team/service selector, all encoded as /o/:org/... with ?tenant= / ?project= query state so the nav shape never changes.

One org in view at a time, switched from the sidebar header, is near-universal (Vercel team switcher top-left, Supabase Feb 2025 org-at-a-time with account menu moved top-right, Sentry OrganizationDropdown in SidebarHeader, GitLab 2023 context header, Clerk OrganizationSwitcher, shadcn sidebar-07). Navigation & shell

Standardise a sticky 48px (h-12) PageActionBar in the shared shell with four slots: SidebarTrigger + vertical Separator, router-derived Breadcrumb (org > scope > resource > detail, every crumb a real landing page), a Tabs slot for per-entity views (Overview / Sessions / Grants / Audit on a latchkey client; Events / Tags / Activity on a tripline issue), and a right-aligned actions slot that always contains a visible '⌘K Search…' input chip (h-8, w-56) plus the account menu.

Tables & density

Ship one DataTable wrapper on TanStack Table v9 (useTable + tableFeatures) with TanStack Virtual under the shadcn Table, exposing density as a data-density="compact|normal|spacious" attribute on the table root that sets --cell-py 4px/8px/12px and --cell-px 8px/12px/16px (28/36/44px rows on 12-13px type, 20px line-height), chosen from a view-options menu and persisted per route in localStorage; defaults: tripline issue list compact, latchkey entity lists normal with a compact toggle, runsheet run history normal. Sizing regimes: client-held sets (stack frames, breadcrumbs, spans, events-for-one-issue) virtualise with fixed row height per density; server-backed lists cursor-paginate at 25-50 rows with 'Previous / Next' and '21–40 of 142' copy and a page-size selector; live streams (runsheet run logs, tripline live events) append behind an 'N new' pill rather than auto-scroll.

Primer DataTable's cellPadding condensed/normal/spacious (4/8/12px block padding) is the reference density implementation and its ListViewDensityToggle persists to localStorage; GitHub Projects (June 2026) and Grafana 12.x expose row height in view options; Datadog Events offers compact-to-expanded density; Vercel design.md limits compact density to dense lookup. Grafana rebuilt its table on a virtualised grid (GA Sept 2025, 41k-row benchmark) and disables virtualisation for dynamic height; Geist Table exposes virtualize plus Previous/Next range copy; Polaris paginates past 50-100 rows; Vercel Runtime Logs uses 'Show New Logs' instead of infinite scroll; shadcn's data-table guide targets TanStack v9.

Tables & density

Provide two row primitives on the same tokens (row height per density, hover bg via alpha neutral, 2px inset focus ring): a ListRow (whole row clickable, primary text + inline 12px muted metadata + status glyph + trailing hover actions) for tripline's issue stream and runsheet run/incident history, and the grid DataTable for tripline p50/p95 tables and latchkey identities/sessions/clients/grants. In the grid: numeric columns and their headers get text-right + tabular-nums (including placeholders and totals), identifiers (session/client/tenant IDs, request IDs, SHAs, ISO timestamps, JWKS kid) render via a shared component in font-mono at 12.5px, empty values render '—' never 'N/A', times are relative ('5h ago') within 7 days then absolute ('Mar 14, 2026') via shared formatters, headers are Title Case nouns like 'Requests (7d)'.

Primer keeps ListView (primary info + metadata + actions) separate from DataTable, which is reserved for flat comparable 2-D data; Geist says use Table only when at least one column is sortable/comparable; Sentry's 2025 issue stream made the whole row clickable with a few aligned columns. Real trends we are deliberately not following

  • Two-tier icon rail + secondary panel (Sentry 2025, Datadog, Atlassian flyouts, shadcn sidebar-09): built for multi-product suites with dozens of areas; our largest app has ~20 pages that fit in 6 label-only groups, the rail costs 74px + 190px of width that p95 tables and stack traces need, and keeping rail group counts identical across a 4-group runsheet and a 6-group latchkey would force fake groups.
  • A distinct sidebar per scope level (Supabase project sidebar, GitLab group/project sidebars): swapping the nav when entering a tenant or project breaks muscle memory and doubles the IA to maintain; Vercel/Sentry-style scope-as-filter keeps one nav and one URL scheme across the three apps.
  • A shell-level AI chat sidebar or assistant drawer (Grafana Assistant, Datadog Bits chat): the only published usage data (Honeycomb) shows NL querying as an onboarding ramp, not a replacement for structured queries; latchkey's identity/grant/session questions are exact-match and audit-sensitive so a hallucinated 'who has access' answer is a liability. At most a per-object summary card and a palette action in tripline, instrumented before expansion.
  • Optimistic-by-default mutations everywhere (Linear local-first, Vercel guideline): correct for tripline triage, wrong for latchkey where revoke session, delete tenant, remove grant and rotate secret are security-relevant and often irreversible; those must be blocking modal or typed-name flows, never rolled back from a toast.
  • Runtime theme generation and user-chosen accents (Linear's base/accent/contrast generator, Radix Themes props): three fixed build-time presets sharing one neutral and differing only in accent is what makes the apps read as one family; a per-user accent picker undermines product recognition and adds a token-validation surface we do not need.
  • Rich, stacking, promise-driven toasts as the primary feedback channel (shadcn July 2026 Toast): Geist and Primer both scope toasts to acknowledgments; failures of a bulk resolve or a permission denial in a 20-section admin must persist inline, so the shell keeps a deliberately plain Toast and invests in Note/InlineMessage instead.
  • Zero-radius 'boxy' terminal styling (shadcn Lyra) and the 'anti-generic' cream + serif + terracotta / near-black + acid-green palettes: both are reactions to template fatigue, but sharp corners fight focus rings and nested inputs in dense forms, and editorial palettes make red/amber/green status tokens harder to read; a low-chroma neutral, 6px radius and one accent is the defensible dev-tool register.
  • Dark-first as a blanket default and light-dark() as the token declaration mechanism: latchkey's admin console is read by support staff in offices and should default to system/light; light-dark() is Baseline 2024 but shadcn's contract, tooling and presets are built on the .dark class remap, so declaring tokens twice per theme stays the cheaper path.
  • Hidden-by-default (offcanvas) sidebar below 1200px (GitLab Pajamas) and Polaris-style automatic table-to-list collapse on narrow screens: the icon rail already reclaims width, and auto-collapsing tripline's p95 or latchkey's grant tables into list rows hides the comparable columns those tables exist for; only latchkey's incident-time phone use warrants an explicit narrow-screen list fallback, opted in per table.
  • Row pinning during live streaming (Sentry Logs, Aug 2026) and Atlassian-style 4px line-height grid snapping: the first is a single-vendor feature whose implementation is unverified and only runsheet run logs would use it; the second is one house rule while Primer and Geist use unitless ratios, so it buys nothing for consistency across our three apps.

Option B, built the way the research says

Take the shadcn/ui token contract on Tailwind v4, which runsheet already runs, generated from OKLCH twelve-step scales: one mauve-tinted neutral shared by all three consoles, fixed-hue status scales (danger, warning, success, info) kept apart from the accent, and the accent as the only per-app variable: indigo for tripline, teal for runsheet, violet for latchkey. That gives one theme, three small accent files, and the family resemblance the research keeps finding in Vercel, Sentry and Supabase.

  1. Publish @triplineid/theme: base.css (Geist Sans and Mono, the 12/13/14/16 scale, 6/8/12px radii, the shared neutral, status and chart scales, light and separately tuned dark) plus tripline.css, runsheet.css, latchkey.css (accent blocks only).
  2. Add Tailwind v4 to the tripline console and move its hand-written CSS onto the tokens; runsheet's portal switches its gray utilities to the tokens.
  3. Copy in the shadcn components both apps need now: button, select, table, badge, dialog. Nothing else until a screen asks for it.
  4. Build the shell once in the theme package: the 240px/48px collapsible sidebar with pinned group and avatar org switcher, the sticky action bar with breadcrumbs, scope filters, ⌘K chip and account, the command palette registry, the density-aware DataTable and ListRow, the right-hand DetailSheet, and the three-tier mutation contract. Each app passes its groups, its entity search and its actions.

If you would rather each app feel like its own product, C is the stronger identity and costs the same. A is the pick only if all three apps are willing to standardise on Radix components. Effort for the shell and theme package is about a week; each app then adopts it in a day or two.
